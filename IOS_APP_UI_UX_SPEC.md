# UI/UX-спецификация TorrServer для iOS

## 1. Назначение документа

Документ описывает визуальную структуру и поведение iOS-приложения, использующего `TorrCore.xcframework` из документа `IOS_C_ARCHIVE_IMPLEMENTATION_PLAN.md`.

Основные пользовательские возможности:

- запуск и остановка torrent-ядра;
- добавление magnet-ссылок, torrent URL и локальных `.torrent`-файлов;
- просмотр списка торрентов;
- просмотр файлов внутри торрента;
- создание ссылки для VLC/Infuse;
- удаление торрента и его кэша;
- просмотр загруженных и активных чанков;
- изменение лимита RAM-кэша;
- просмотр скорости, peers, заполнения кэша и состояния фоновой streaming-задачи.

Спецификация ориентирована на SwiftUI и iOS 26+. Интерфейс должен быть полноценным iPhone-приложением, а не копией существующей веб-страницы TorrServer.

## 2. Принципы интерфейса

1. Ядро всегда имеет явно видимое состояние: выключено, запускается, работает, останавливается или завершилось ошибкой.
2. Опасные операции отделены от обычных: удаление данных требует подтверждения.
3. Технические данные доступны, но не мешают основному сценарию «добавить → выбрать файл → смотреть».
4. Состояния отображаются цветом и текстом. Нельзя полагаться только на цвет.
5. Все длительные операции отменяемы.
6. Интерфейс корректно работает при недоступном ядре, отсутствии сети и незавершенной metadata.
7. Размеры файлов, память и скорость показываются в человекочитаемом формате.
8. Не обновлять весь SwiftUI tree каждую секунду: частые метрики локализовать во view model отдельных экранов.
9. Поддержать светлую и темную темы, но основная визуальная проверка должна выполняться в темной теме.
10. Использовать системные шрифты, Dynamic Type, VoiceOver labels и стандартные iOS gestures.

## 3. Информационная архитектура

Основная навигация — `TabView` с тремя разделами:

```text
┌──────────────────────────────────────┐
│ Торренты │ Активность │ Настройки    │
└──────────────────────────────────────┘
```

### 3.1. Торренты

Главный пользовательский раздел:

- состояние ядра;
- список добавленных торрентов;
- поиск и фильтрация;
- добавление torrent;
- переход к деталям и файлам.

### 3.2. Активность

Технический мониторинг:

- активные streaming sessions;
- суммарная скорость;
- peers;
- RAM cache;
- disk cache;
- карта чанков выбранного torrent/session;
- события и диагностические ошибки.

### 3.3. Настройки

- включение/выключение ядра;
- автоматический запуск;
- лимит RAM-кэша;
- лимит disk cache;
- connection limits;
- upload policy;
- поведение после закрытия внешнего плеера;
- очистка кэша;
- диагностическая информация.

## 4. Визуальный стиль

### 4.1. Цвета

Использовать семантические SwiftUI colors и небольшой собственный набор:

| Роль | Светлая тема | Темная тема | Использование |
|---|---|---|---|
| Accent | системный синий | системный синий | кнопки, выбранные элементы |
| Success | системный зеленый | системный зеленый | ядро работает, chunk загружен |
| Active | cyan/teal | яркий cyan | chunk загружается, streaming |
| Warning | системный оранжевый | системный оранжевый | metadata, reconnect, высокий RAM |
| Destructive | системный красный | системный красный | ошибки, удаление, stop |
| Cached RAM | зеленый | зеленый | chunk находится в RAM |
| Cached Disk | синий | синий | chunk находится на диске |
| Requested | cyan | cyan | chunk запрошен внешним player |
| Queued | желтый | желтый | chunk поставлен в очередь |
| Missing | secondary fill | secondary fill | chunk отсутствует |
| Failed | красный | красный | ошибка проверки/загрузки chunk |

Цвета карты чанков должны иметь различимую яркость. Для VoiceOver каждый chunk получает текстовое состояние.

### 4.2. Типографика

- Заголовок экрана: `.largeTitle` или `.title2` в зависимости от навигационного контекста.
- Название torrent: `.headline`.
- Основная метрика: `.title3.monospacedDigit()`.
- Вторичные значения: `.subheadline`/`.caption` с `foregroundStyle(.secondary)`.
- Infohash, URL, port: `.caption.monospaced()`.
- Скорости и размеры: `monospacedDigit()` для отсутствия скачков ширины.

### 4.3. Карточки

На iPhone использовать системный grouped background и карточки с:

- радиусом 14–16 pt;
- внутренним padding 12–16 pt;
- минимальным количеством теней;
- `Material` только для плавающих панелей;
- четким разделением primary action и метрик.

## 5. Глобальная модель состояний

### 5.1. Состояние ядра

```swift
enum CoreState {
    case stopped
    case starting
    case running
    case stopping
    case failed(CoreError)
}
```

Отображение:

| Состояние | Индикатор | Текст | Доступное действие |
|---|---|---|---|
| stopped | серый circle | «Ядро выключено» | «Запустить» |
| starting | progress | «Запуск ядра…» | «Отмена» при поддержке |
| running | зеленый circle | «Ядро работает» | «Остановить» |
| stopping | progress | «Остановка…» | действия заблокированы |
| failed | красный warning | короткая ошибка | «Повторить» / «Подробнее» |

### 5.2. Состояние torrent

```swift
enum TorrentUIState {
    case saved
    case fetchingMetadata
    case ready
    case streaming
    case downloading
    case paused
    case unavailable
    case failed
}
```

### 5.3. Глобальная блокировка действий

Если ядро выключено:

- список сохраненных торрентов остается видимым;
- добавить torrent можно либо после автоматического запуска ядра, либо приложение сначала предлагает запустить ядро;
- просмотр сохраненной metadata допустим;
- создание stream URL и chunk monitoring недоступны;
- недоступное действие объясняет причину, а не просто становится серым без подсказки.

### 6.2. Header ядра

Компактная карточка всегда находится сверху списка.

Содержит:

- status dot и текст;
- версию ядра по tap или в context menu;
- текущие download/upload speed;
- число peers;
- использование RAM cache;
- кнопку запуска или остановки.

Кнопка stop не должна выглядеть как большая destructive action на главном экране. Использовать иконку `stop.circle`, а подтверждение показывать только при активном stream/download.

Если есть активная external-player session, карточка показывает:

```text
VLC подключен • 1 поток
```

### 6.3. Строка torrent

Содержимое:

- постер, если задан; иначе иконка типа контента;
- title, fallback — metadata name, fallback — сокращенный hash;
- общий размер;
- состояние;
- progress или skeleton;
- скорость и peers только при активности;
- число файлов;
- индикатор сохраненного disk cache;
- индикатор внешнего клиента, если подключен VLC/Infuse.

Не показывать одновременно больше трех вторичных метрик. Расширенные значения находятся в detail screen.

### 6.4. Жесты строки

Tap:

- открыть Torrent Detail.

Swipe leading:

- «Смотреть», если metadata и файлы готовы.

Swipe trailing:

- «Удалить»;
- дополнительное действие «Остановить», если torrent активен.

Context menu:

- Смотреть;
- Копировать magnet/infohash;
- Показать чанки;
- Остановить torrent;
- Удалить.

### 6.5. Empty states

Ядро включено, торрентов нет:

```text

Добавьте magnet-ссылку или откройте

```

Ядро выключено:

```text

          [Запустить]
```

При наличии сохраненных торрентов не заменять список empty-state экраном; показывать сохраненные карточки в disabled/read-only состоянии.

### 7.1. Открытие

Кнопка `+` показывает bottom sheet `Добавить torrent`.

На широком iPad — form sheet.

Поддерживаемые источники:

- вставка из clipboard только по явному нажатию пользователя.

### 7.3. Валидация

- выполнять локальную синтаксическую проверку до C ABI;
- показывать inline error под полем;
- не закрывать sheet при ошибке;
- блокировать повторный submit;
- при выключенном ядре показать toggle/предложение «Запустить ядро и добавить».

### 7.4. После добавления

Sheet закрывается после получения hash, а новая строка появляется наверху:

```text
Получение metadata…
Ищем peers • 12 с
```

Показывать кнопку отмены при длительном ожидании. Не блокировать весь экран.

Основные:

- torrent size;
- loaded/completed bytes;
- download speed;
- upload speed;
- active peers / total peers;
- seeders;

- disk cache occupied.

Технические метрики помещать в раскрывающийся блок «Подробнее»:

- pending peers;
- half-open peers;
- chunks read/written/wasted;
- infohash;
- tracker list;
- created timestamp.

### 8.3. Список файлов

Каждая строка:

- media/file icon;
- полный filename с переносом максимум в две строки;
- parent path вторичной строкой;
- size;
- cached percent;
- play button для поддерживаемого внешнего открытия;
- subtitle badge, если файл похож на субтитры.

Сортировка по текущей логике TorrServer должна совпадать с `fileId`, иначе внешний URL будет указывать не на тот файл. Swift хранит и передает ID, полученный от Go, а не вычисляет его по позиции строки.

Фильтры:

- Все;
- Видео;
- Аудио;
- Субтитры;
- Прочее.

## 9. Сценарий «Смотреть во внешнем плеере»

### 9.1. Player chooser sheet

После нажатия play:

```text
┌──────────────────────────────────────┐
│ Смотреть                             │
│ Episode 01.mkv                       │
│                                      │
│ [Открыть в VLC]                      │
│ [Открыть в Infuse]                   │
│ [Выбрать приложение…]                │
│ [Копировать локальную ссылку]        │
│                                      │
│ ○ Подготовка потока…                 │
└──────────────────────────────────────┘
```

Перед активацией кнопок приложение:

1. проверяет ядро;
2. вызывает `TS_PrepareStream`;
3. регистрирует `BGContinuedProcessingTask`;
4. проверяет `/health` или HEAD stream URL;
5. активирует способы открытия.

Если background task не стартовал, URL не передавать внешнему приложению.

### 9.2. Возврат в TorrServer

После возврата показывать banner:

```text
VLC подключен
Episode 01.mkv • 46% загружено
[Показать активность] [Остановить]
```

Если VLC временно отключился, использовать состояние «Ожидание переподключения» с countdown grace timeout.

## 10. Удаление torrent

### 10.1. Confirmation dialog

Нельзя объединять удаление записи и удаление кэша в неясную кнопку.

```text
Удалить torrent?

«Название» будет удален из списка.

( ) Удалить только из списка
(●) Удалить также 1.8 GB кэша

[Отмена]                  [Удалить]
```

Если torrent активен:

```text
Сейчас файл передается в VLC. При удалении
воспроизведение будет остановлено.
```

### 10.2. Поведение

- сначала отменить stream sessions;
- дождаться закрытия readers с ограниченным timeout;
- удалить torrent из ядра/БД;
- удалить cache только при выбранной опции;
- при частичной ошибке показать, что именно было удалено;
- UI row исчезает после подтвержденного результата Go, а не оптимистично до него.

## 12. Визуализация чанков

### 12.1. Цель

Карта должна отвечать на вопросы:

- какие pieces уже загружены;
- где сейчас читает VLC/Infuse;
- что находится в RAM;
- что находится на disk;
- что загружается или стоит в очереди;
- какие ranges относятся к выбранному файлу.

```text
│ ■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■     │
│ ■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■     │

```

### 12.3. Представление одного chunk

Не создавать тысячи отдельных SwiftUI `View`, если torrent содержит много pieces. Это вызовет лишнюю память и layout cost.

Рекомендуемая реализация:

- custom `Canvas`;
- вычислять количество колонок по доступной ширине;
- размер клетки 4–8 pt в зависимости от масштаба;
- промежуток 1 pt;
- отрисовывать только видимый диапазон при zoom/scroll;
- входные состояния передавать компактным массивом enum/bytes;
- diff обновлять только измененные chunks.

Альтернатива для первого MVP — `LazyVGrid` при количестве pieces менее 2000 и Canvas для больших карт.

### 12.4. Приоритет цвета

Один chunk может одновременно находиться на disk и быть текущим requested. Нужен порядок визуальных приоритетов:

1. Failed — красная заливка;
2. Requested/current reader — cyan заливка или яркая обводка;
3. Loading — анимированная/пульсирующая cyan обводка;
4. RAM — зеленая заливка;
5. Disk — синяя заливка;
6. Queued — желтая заливка;
7. Missing — нейтральная заливка.

Анимация должна быть отключена при Reduce Motion.

### 12.5. Interaction

Tap на chunk показывает inspector popover/sheet:

```text
Piece 824
Диапазон файла: 1.42–1.43 GB
Размер: 2 MB
Состояние: RAM cache
Приоритет: Now
Последний доступ: 4 секунды назад
```

Pinch:

- zoom карты;
- при увеличении показывать номера every N chunks.

Long press:

- только диагностическая информация;
- ручное изменение priority не включать в MVP, чтобы не ломать streaming algorithm.

### 12.6. API для карты

`TS_StreamStatus` не должен возвращать огромный JSON с тысячами объектов каждую секунду.

Предпочтительные варианты:

1. отдельный `TS_ChunkMap(sessionID)` с компактным base64/byte encoding;
2. JSON ranges одинаковых состояний;
3. incremental changes с generation counter.

Рекомендуемый формат:

```json
{
  "generation": 42,
  "pieceLength": 2097152,
  "pieceCount": 2114,
  "fileFirstPiece": 120,
  "fileLastPiece": 1350,
  "readerPieces": [824],
  "ranges": [
    {"from":120,"to":510,"state":"disk"},
    {"from":511,"to":552,"state":"ram"},
    {"from":553,"to":558,"state":"loading"}
  ]

```

Добавить в C ABI:

```c
char* TS_ChunkMap(const char* request_json);
```

Request может включать предыдущую generation, чтобы Go вернул `notModified` или delta.

## 13. Настройка RAM-кэша

### 13.1. Размещение

Настройки → Кэш → Оперативная память.

```text
┌──────────────────────────────────────┐
│ ‹ Настройки     Оперативная память   │
│                                      │
│ Лимит RAM-кэша                       │
│             128 MB                   │
│ 32 MB ├──────●──────────────┤ 512 MB │
│                                      │
│ [64] [128] [256] [Другое]            │
│                                      │
│ Сейчас используется                  │
│ [█████████████░░░░░] 82 MB           │
│                                      │
│ Рекомендация для этого устройства    │
│ 128 MB                               │
│                                      │
│ Изменение применяется к новым        │
│ readers. Для полного применения      │
│ может потребоваться перезапуск ядра. │
│                                      │
│              [Применить]             │
└──────────────────────────────────────┘
```

### 13.2. Диапазон

Предлагаемые значения:

- минимум: 32 MiB;
- presets: 64, 128, 256, 512 MiB;
- максимум рассчитывать по physical memory и ограничить безопасным значением;
- для старых/малопамятных устройств не предлагать 512 MiB;
- отображать MiB пользователю как MB, но хранить точные bytes.

Не привязывать maximum только к `ProcessInfo.physicalMemory`: iOS не гарантирует приложению всю физическую память. Использовать консервативный продуктовый cap и device testing.

### 13.3. Предупреждения

При высоком значении:

```text
Высокий лимит может привести к завершению
приложения системой при нехватке памяти.
```

При попытке поставить значение меньше текущего использования:

```text
Кэш будет постепенно уменьшен до нового лимита.
Активный поток может временно загружать части повторно.
```

### 13.4. Применение

Нужен новый C ABI:

```c
char* TS_GetSettings(void);
char* TS_UpdateSettings(const char* settings_json);
```

Request:

```json
{
  "ramCacheLimitBytes": 134217728
}
```

Go должен вернуть:

```json
{
  "applied": true,
  "requiresCoreRestart": false,
  "effectiveRamCacheLimitBytes": 134217728
}
```

Предпочтительно реализовать runtime resize:

- обновить `settings.BTsets.CacheSize`;
- изменить capacity активных caches под mutex;
- при уменьшении запустить безопасный eviction;
- не удалять pinned/current reader pieces;
- никогда не блокировать Swift call до полного eviction;
- вернуть целевое значение немедленно, а фактическое использование уменьшать асинхронно.

Если runtime resize невозможно на первом этапе, UI явно показывает необходимость перезапуска и предлагает:

```text
[Позже] [Перезапустить ядро]
```

При активной VLC-session автоматический restart запрещен без отдельного подтверждения.

### 14.1. Core toggle

Toggle включения ядра является асинхронным control:

- при включении показывает progress вместо мгновенной смены состояния;
- если Start завершился ошибкой, toggle возвращается назад и появляется error sheet;
- при выключении без активных sessions остановка выполняется сразу;
- при активных sessions появляется подтверждение.

Подтверждение:

```text
Остановить ядро?

Активный поток в VLC будет прерван.

[Отмена] [Остановить]
```

### 14.2. Очистка кэша

Разделить:

- очистить неактивные chunks;
- очистить весь disk cache;
- очистить RAM cache;
- удалить завершенные/неиспользуемые torrents — отдельная операция, не часть cache cleanup.

Активные/pinned chunks не удалять без остановки session.

## 15. Ошибки и уведомления

### 15.1. Toast/banner

Для кратких обратимых событий:

- URL скопирован;
- torrent добавлен;
- лимит применен;
- reconnect произошел;
- cache очищен.

### 15.2. Inline error

Для ошибки конкретной карточки:

- metadata timeout;
- tracker unavailable;
- torrent не имеет peers;
- выбранный файл исчез;
- stream reconnecting.

### 15.3. Alert/sheet

Для:

- core start failure;
- database corruption/open failure;
- недостатка disk space;
- background task rejected;
- VLC/Infuse не установлен;
- destructive confirmation.

Error sheet содержит:

- понятный заголовок;
- пользовательское объяснение;
- технический error code мелким текстом;
- Copy diagnostics;
- Retry, если операция повторяема.

## 16. Accessibility

- Все status dots имеют VoiceOver text.
- Chunk Canvas предоставляет summary accessibility element и возможность открыть inspector по диапазону; не создавать тысячи accessibility elements по умолчанию.
- Минимальная зона нажатия 44×44 pt.
- Поддержать Dynamic Type без обрезания названий torrent/file.
- Не кодировать состояние только цветом.
- Поддержать Reduce Motion.
- Скорость озвучивать как «8,4 мегабайта в секунду», а не набор символов.
- Progress bars имеют `accessibilityValue` в процентах и bytes.

Базовые UI-запросы:

| UI действие | C ABI |
|---|---|
| Запустить ядро | `TS_Start` |
| Остановить ядро | `TS_Stop` |
| Статус header | `TS_EngineStatus` |
| Добавить torrent | `TS_AddTorrent` |

## 21. UI Definition of Done

Интерфейс считается реализованным, когда:

- состояние ядра всегда видно и соответствует реальному `TS_EngineStatus`;
- Start/Stop нельзя случайно вызвать несколько раз параллельно;
- активный stream защищен подтверждением перед Stop;
- magnet, hash, URL и `.torrent` добавляются из одного понятного sheet;
- metadata state не блокирует список;
- torrent можно удалить отдельно от кэша или вместе с ним;
- пользователь может выбрать файл и открыть URL в VLC/Infuse;
- background task rejection показывается до открытия внешнего player;
- Activity tab показывает реальные streams, peers, speeds, RAM и disk usage;
- chunk map различает missing, queued, loading, requested, RAM, disk и failed;
- карта остается плавной на torrent с десятками тысяч pieces;
- лимит RAM меняется в bytes без рассинхронизации UI и Go settings;
- UI объясняет, нужен ли restart ядра;
- ошибки имеют стабильный технический code и понятный текст;
- интерфейс работает в dark/light mode, Dynamic Type и VoiceOver;
- все destructive действия подтверждаются;
- polling останавливается при выключенном ядре и уходе ненужных экранов;
- Swift не протекает C strings и всегда вызывает `TS_Free`.

## 22. Главный пользовательский сценарий

```text
Запустить ядро
      ↓
Добавить magnet/.torrent
      ↓
Дождаться metadata
      ↓
Выбрать видеофайл
      ↓
Подготовить stream + background task
      ↓
Открыть VLC/Infuse
      ↓
Смотреть прогресс и чанки в TorrServer
      ↓
Закрыть player или остановить session
```

Основной экран должен делать этот сценарий коротким. Карта чанков, тонкие настройки памяти и технические метрики являются вторым уровнем интерфейса и не должны усложнять добавление и запуск просмотра.
